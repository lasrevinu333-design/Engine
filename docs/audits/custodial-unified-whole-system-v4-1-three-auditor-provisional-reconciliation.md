## 5. GPT-5.5 Instant unique architecture blockers

These findings are not contradicted by the other reports and should be treated as provisionally confirmed pending primary-evidence verification and GPT-5.6 review.

### I-01 — Complete Capability–Authority–Contract–Evidence Matrix is missing

The 252-capability canon, authority register, gates and architecture are separate artifacts. The package does not contain one normalized row per capability joining:

- purpose and actor;
- source evidence;
- current and target writers/readers;
- canonical fact/command/event/projection;
- architecture/API/UI contracts;
- security/privacy;
- retention;
- migration/rollback;
- gates;
- automated tests;
- physical tests;
- final disposition.

A reverse registry is also required:

`architecture object → actor → operational purpose → source capability → authority → proof`.

### I-02 — Manager Attendance Context lacks an exact contract

Attendance is present in v17, backend/source evidence and the capability canon, but v4.1 does not fully define:

- source authority;
- cache and freshness;
- stale/unavailable state;
- privacy and fields;
- Manager-only default;
- AI read permission;
- retention;
- explicit prohibition on schedule/employment/eligibility mutation.

Default: informational only and never Employee Home.

### I-03 — Confidential accommodation rationale is not separated from operational effect

The target must define two separate objects:

1. neutral operational constraint effect; and
2. confidential justification under a restricted role and separate retention policy.

Private rationale must never appear in Employee Schedule, employee alerts, Read Only, ordinary Dashboard, analytics, exports, Memphis AI, contractor links or guest surfaces.

### I-04 — P0 alert preemption conflicts with fixed audio cadence

The exact contract is:

`chime → complete speech → chime → identical speech → silence`.

V4.1 priority/preemption language does not completely define what happens if a P0 alert arrives during either cycle.

Provisional safest default: no speech preemption; queue alerts unless a separately approved device-safety emergency contract is proven necessary.

### I-05 — External/generated migration artifacts are not governed

A Library SQL seed derived from the candidate workbook can delete/reseed schedule state. It is outside the admitted repository/release tuple.

Required response:

- inventory and digest all external SQL/data artifacts;
- mark them candidate, quarantined, retired or admitted;
- prohibit manual production SQL outside admitted migrations;
- preserve useful artifacts as historical evidence only;
- release gate fails if an unadmitted executable seed remains referenced.

### I-06 — Frozen evidence precedence manifest is missing

Create a manifest containing:

- path/name;
- digest;
- evidence type;
- date;
- controlling status;
- supersedes/superseded-by;
- candidate versus approved;
- source confidence;
- related gates;
- workbook tab inventory.

### I-07 — Employee Event projection wording requires a formal contract

Employee-visible event states should distinguish:

- Information only;
- Work may change — manager review pending;
- Approved work notice;
- Cancelled/superseded.

Only an approved requirement or ownership input may produce imperative work language.

### I-08 — Weather needs explicit disposition

Weather should be either:

- optional Manager-only informational context; or
- retired.

It must never return to Employee Home or become schedule authority without separate approval.

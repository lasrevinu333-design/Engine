# Finite native notification mirror — conditional source stage

This stage constructs the accepted H01/EXCAP-P01 native-to-in-app mirror, not a new ingress, receipt store, principal authority or audio engine. It does not activate either production factory, install a qualified clock profile, create empty provider state, change the manifest, or alter CLEANING/Start/removal policy.

The same application-context owner and encrypted journal issue one ephemeral attachment bound to the actual plugin object. Seven additive exports allow attach, positive stopped/readback, next claim, current claim state, finite action, exact visual retirement and detach. There is no generic execution, content, identity, generation, clock or received/sent receipt setter. The native plugin publishes only coalesced runtime-incarnation/journal-revision hints on the UI thread. Hints cannot select or authorize a record.

Every employee page uses the existing shared bridge. It subscribes before native attachment/snapshot and pulls immediately regardless of retained hints. One serialized drain pulls at most eight claims per execution, schedules at most one next turn, and shares one visible/current sixty-second repair timer. Hide, detach and identity loss retire listener/timer/callbacks; reattachment subscribes afresh. Late old native results and callbacks cannot render or settle a successor.

The existing `memphis-device-reminders.js` card and audio engine are the only renderer. Native full-text payloads enter its actual `showAcceptedNotification`; native durable `displayed` and `audio_started` precede sound/vibration/wake. Open commits the original action before waiting for the original two-cycle episode and uses the exact native route. Destination readback settles navigation without synthesizing another action. Dismiss removes only the visual and does not interrupt running audio or become an ACK. Acknowledge commits its distinct original action, then cancels its exact presentation/audio. Completed audio leaves an unhandled visual persistent across reattachment while the current qualified window is live; audio does not replay. IN_PROGRESS remains uncertain after process death.

Before audio-capable claims on any new attachment, the actual renderer must observe its own HTMLAudio paused, SpeechSynthesis speaking/pending false, and no remaining owned sequence/tone/speech/oscillator/timer. A void cancel/Fully call is not proof of silence. Unknown readback blocks; unrelated legacy/help/debug audio is never canceled to acquire this lane. Interrupted positively stopped audio releases only the ephemeral capability through `audio_stopped`, leaving persisted IN_PROGRESS, not COMPLETED. A never-started retired capability releases FIFO without changing persisted PENDING. Physical WebView/TTS/route/Lock Task behavior remains an evidence gate.

Source proof: actual native owner/journal tests, typed JS facade/coordinator tests, actual published bridge/reminder DOM/audio tests, shared bridge construction/lifecycle tests, exact36-method DEX/schema allowlist, and portable full-byte reverse-delta guards. The original engine/CLEANING/NFC/manifest hashes remain pinned. Old source guards execute without Git in PATH. Two demonstrated fail-before regressions preserve provenance: completed audio suppressed an unhandled visual, and a never-started navigation offer starved the next FIFO item.

Remaining source/authority: required non-LOCATION/LUNCH kinds; parent-owned LUNCH backend integration; production entry/store construction and selection; permanent-denial diagnostics and cleanup scheduling; explicit historical-visual policy across expiry (current native claim rule only permits expired durable Open); and legitimate exact-platform worst-case interval qualification. Profiles.NONE and both factories remain SUSPENDED. No bounded test, synthetic callback, provider acceptance or source compilation is a release or physical result.

## Callable contract

`NativeProviderRegistrationCoordinator.registerWithClock(attempt, statusOnly)` returns an `ExchangeResult`. A confirmed result contains `NativeProviderClockExchange.Settlement`: the exact durable registration, original principal digest, native engine revision, provider invalidation epoch, and an explicitly `Unqualified` clock candidate. Waiting/busy/already-confirmed-without-refresh results have no candidate. The compatibility `register` method performs the same validation and returns only the status; it cannot admit time.

Internal `statusOnly=true` now supports the exact current confirmed registration as well as an ambiguous pending operation. Confirmed status sends no token and rewrites neither activation nor the original admission or capture. A prepared successor generation prevents old confirmed status. Pending original operations are still resolved before a newly captured token. HTTP loss preserves that original operation; a fresh status request gets a new native HTTP request ID, not a new registration operation.

`NativeProviderHttp` pins the existing HTTPS origin and four exact typed paths, signs the exact serialized raw bytes with the existing native credential HMAC authority, and records that signature's fresh random request UUID/path/body SHA-256. Native reading A is before opening the connection; B is after bounded full body consumption. The native adapter reads Android boot count around `elapsedRealtime()` and refuses unavailable or inconsistent boot identity. It does not consult wall time, NFC's bridge-fed anchor, FCM, Intent or WebView values for these observations. Wall time remains only the existing HMAC timestamp admission input; this stage does not relax that pre-existing server policy.

Successful register/status wire envelope is exactly:

```json
{"ok":true,"data":{"schema":"custodial.native-provider-registration.v1","...":"unchanged admission fields"},"clock":{"native_request_id":"fresh attestation request UUID","server_now":"2026-10-02T06:00:00.123456Z","valid_until":"2026-10-02T06:15:00.123456Z"}}
```

The example `data` abbreviation is explanatory, not valid wire data. Actual admission keys remain strict. The clock block has exactly three string fields, six-fraction canonical UTC timestamps, exact request nonce, positive horizon no greater than900000000 microseconds, same native boot, nondecreasing A/B and a necessary raw-duration rejection at45000ms. Native microseconds use checked signed64-bit arithmetic. **Raw duration below45s is not the accepted qualified upper-bound proof.** No q_ns/p_ppm values, inferred uncertainty, authoritative interval, `authenticatedAt`, clock store, profile or effect permission are produced.

The engine rechecks exact engine phase/revision, full principal and provider epoch after HTTP before validating this strict envelope and settling the original operation. Registration facts and clock evidence remain separate. The old admission-only validator is a native pure-journal test seam; live HTTP only uses `validateExchange`, which requires the separate clock block. There is no old-envelope wire fallback. The returned candidate is evidence at settlement, not a reusable authorization token: a future owner must still revalidate current native identity, boot, age, expiry and invalidation immediately before use.

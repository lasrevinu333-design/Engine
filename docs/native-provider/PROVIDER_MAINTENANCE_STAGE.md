# Bounded native provider diagnostics and maintenance

Source-only additive stage on0415699e. Existing factory selection remains SUSPENDED
and Profiles.NONE; no production qualification, backend policy, historical restoration,
new notification kind, original cleaning/Start authority or enrollment changes.

The same runtime captures one full native-principal/engine-revision/provider-binding/
invalidation-epoch invocation scope before HTTP. A failed pass may save one encrypted,
finite last-local-failure diagnostic after revalidating that original scope. Diagnostics
are non-authoritative and scoped to the native invocation, NOT a server operation
outcome. No raw error/body/token/seal is stored or returned. Current local status returns
only reason, handling and durable observation, not principal/operation IDs. A successful
later pass does not erase the historical failure or turn it into an active denial.

Diagnostic readback failure leaves the original exception primary with the diagnostic
failure suppressed. Identical repeated failures do not churn the store. A stale scope
cannot write under a successor or become current after A->B->A/unavailable->A/removal.
The normal metadata record is bounded; if capacity prevents writing it, the existing
reserved CAPACITY_PRESERVED diagnostic remains the owner. A corrupt/missing key is
not regenerated, and no diagnostic can clear protected bytes to make room.

Current strict register/inventory/events validators provide no authenticated exact
original-binding permanent-denial response. HTTP401/403, malformed bodies, timeout,
or a generic exception therefore do NOT establish revocation. The finite classifier
does not change retry/settlement policy or authorize credentials repair. Definitive
remote-denial suppression remains a source-contract prerequisite, not runtime-only
proof. Existing native removal/foreign/corrupt fences still suspend their actual scope.

After a bounded synchronization pass, the runtime re-observes qualified native time
after effects, revalidates current native authority, and calls the existing journal
compactor with maximum16. The complete compaction method is byte-identical: earliest
endpoint, fresh usable sample, original settled receipts, terminal visual state, no
pending action/navigation/mirror/OS cancellation, uncertainty and exact48h tombstone
retention remain mandatory. Unknown time skips cleanup. Compaction's existing recovery
epoch schedules the same inventory path; no new service, clock, deadline or eviction.

Source ownership and byte preservation are enforced by provider-maintenance-contract-tests.mjs
and a tracked exact reversible delta before older mirror/composition/interval guards.
NativeProviderMaintenanceTest and FailureDispositionTest execute actual native owners
with synthetic clock/network edges. None is independent audit, real provider delivery,
Android adapter/KeyStore execution, TTS/Lock Task or final release acceptance.

# Native provider local lifecycle/removal source stage

This is the bounded local-preservation slice, not the complete effect owner. Both component/ingress factories remain literal `SUSPENDED`. No manifest/index/service activation, app assembly, actual provider, phone or release action.

One application-context runtime lazily constructs `NativeProviderRuntimeOwner` only when the provider namespace already contains retained state. Empty suspended installations do not create provider keys. Startup/resume recovers durable current-native principal/removal fencing and retries only exact pending OS cancellations; it cannot display, authorize a clock, register/send, create a receipt, or start an Activity. Its claims are process/attachment-local and invalidated on missing/changed current identity/revision. Unavailable authority is not falsely classified as removal. Full original provider ciphertext and event identities survive retirement and enrollment-only key finalization.

`NativeProviderAuthority` is the shared reconciliation interpretation used by registration and the local owner: actual v1/v2 native principal, engine→provider lock order, durable journal readback, no repair/synthetic principal. `NativeProviderRemovalCoordinator` wraps the original Activity-backed native-presence gate and original engine removal. It reconciles all outcomes; canceled ACTIVE removal does not retire. A provider durable-fence failure blocks enrollment key finalization. Original removal errors retain added fence failures as suppressed errors, not success. OS cancellation absence is confirmed per exact tag; cancellation failures remain durable, never `cancelAll` or queue deletion. No provider key deletion is introduced.

Important inherited limitation: `VaultEngine.removeEnrollment` remains synchronized through `transport.remove`. The wrapper adds no network monitor and never holds the provider lock across that call; it does NOT make the inherited engine HTTP lock-free. A future coordinated change would split durable-intent/credential capture from network and original revision/operation settlement, with a single-flight attempt and loss/retry/current-owner race tests. Do not change this by merely relaxing a test.

Validation: new actual engine/journal/runtime/removal unit cases cover both native principal lineages, cancellation, durable readback failure/ambiguous commit, key separation, original errors, native unavailability, assignment change, exact cancellation restart and original lost response/idempotent retry. Legacy test transport explicitly supplies a synthetic exact migrated-credential removal receipt; no provider/backend acceptance is inferred. Source contracts normalize only the exact approved plugin lifecycle additions and retain full remaining plugin/NFC equality. Three preexisting SQL-fixture readers now use byte-equivalent `readAllBytes` plus UTF-8 because Android's compile API does not expose `Files.readString`.

## One authority, finite work, original facts

`CustodialNativeRuntime` keeps its single application-context engine, provider coordinator and retained-state journal. Empty startup does not create a provider namespace/key, obtain a token, schedule a job or perform an effect. If exact Android platform identity is unavailable, the existing local-only removal/cancellation owner remains available without guessing a profile. `AndroidProviderPlatform` reports elapsedRealtime API/build/device identity only; it supplies no accuracy or rate bound.

The package-private `NativeProviderRuntimeOwner.Delivery` takes exact native profiles/platform/readings, app identity, typed HTTP, existing system-job scheduler and native-token read. A legitimately qualified matching profile is a prerequisite, not an optional default. `NativeProviderRuntimeOwner` implements existing component and ingress interfaces using the SAME journal, engine, claims, display driver, registration and clock ownership. There is no second enrollment, journal, receiver loop, executor or clock store.

`synchronize(invocation)` is one singleflight pass over the caller's bounded system-job budget:

1. Resolve the actual native principal, persist/retry original registration, or perform one same-worker token read if missing. Fresh status is used when the original clock observation is unknown. Lost response does not invent a new operation or registration generation.
2. Resume original bounded/frozen inventory, retaining its exact authenticated response and original arrival evidence. Registration/inventory/events HTTP is outside engine and provider monitors; inherited caller-held monitors are rejected before network. Settlement revalidates original state.
3. Inspect the bounded native quarantine (maximum256) with a fresh clock observation per admission. Expired entries are preserved, but a prefix of them cannot starve a later valid entry. No expired ciphertext is deleted to advance the queue. Existing inventory-page and event-batch limits remain unchanged.
4. Drain at most16 original pending receipts, perform at most32 exact pending cancellations, and present at most8 NEW OS items. Already-displayed entries do not consume the8 new-display budget. Every effect rechecks current native authority; disabled OS notifications do not manufacture a display receipt.

Removal/revision/assignment-epoch changes invalidate the original response or claim; process-local overlap cannot create a second HTTP owner. Original cached Open is committed before a same-app launch. Open does not schedule a competing cancellation before the launch; the exact OS attempt is retired afterward. Local Dismiss never creates a server ACK. An ACK remains a distinct original receipt. No global notification cancellation or external intent route is added.

## Native FIFO and interrupted audio

Every NEW admitted inbox record stores the original encrypted commit revision as `admission_ordinal` in the same atomic write as the original received event. Native enumeration sorts that ordinal, not a random hash/UUID or reconstructed wall time. Duplicate/lost-return admission preserves the original ordinal and event. An older interval inbox record lacking an ordinal is preserved and fails closed with `custodial_provider_admission_order_unavailable`; its original receipts can still drain. Historical point records are unchanged and remain non-authoritative.

Only durable `PENDING` audio is offered. Restarted `IN_PROGRESS` is neither replayed nor relabelled `COMPLETED`. One offered/current audio capability gates the next FIFO claim. Dismiss retires the visual but does not release active speech; only that attachment's actually-started completion may do so. An unused offer can be retired after Dismiss/ACK or loss of live time without changing the durable speech fact. No automatic completed callback is synthesized. Detach/process-death invalidates callback authority.

## Remaining gates — source versus configuration

- SOURCE: export finite attachment-bound claim/action/retire/isCurrent APIs through the actual plugin, subscribe-before-read retained/coalesced native observer, existing in-app visual/audio FIFO consumer and ACK/removal cancellation. The current native-only methods are not a JavaScript integration. Activity/native cancellation must actually stop/reconcile the current audio before a new attachment starts speech; capability invalidation alone is not proof that a physical TTS engine stopped. Preserve the accepted visible60s bounded repair and same-app kiosk contract.
- SOURCE: production entry construction and empty-to-enrolled provider store admission remain deliberately unselected. Required MESSAGE/SCHEDULE/EVENT/LUNCH canonical reservation, sender, native strict payload, inventory, receipt and per-kind invalidation are not closed by this LOCATION/LUNCH-parser composition. Current receipt SQL still admits LOCATION only. No generic payload/parser fallback is supplied.
- SOURCE: operational integration must give typed permanent-denial/repair diagnostics and exact cleanup scheduling. A retained expired quarantine is preserved here; `pendingWork` conservatively reports retained work while a completed bounded pass can classify it drained. Existing JobService catch uses retained pending state and system backoff for transport errors; this stage does not claim a completed durable permanent-authorization-denial policy. Cleanup predicates exist in the journal but this composition does not invoke compaction. These are not physical-only gates.
- QUALIFICATION: parent must obtain defensible whole-age worst-case resolution/rate/horizon evidence for exact elapsedRealtime API/build/device and permitted sleep/power/temperature conditions, then pin and independently review the profile. API names, TLS authentication and finite observed averages are not such a guarantee. No q_ns/p_ppm defaults, server-now-as-point shortcut, JS clock or CLEANING authority substitution.
- REVIEW/CONFIGURATION: per-kind currentness contract and changed-input independent review; exact backend route/provider/project/credential and native permission/containment configuration. No new resource or credential is created by this source stage. Later artifact/runtime acceptance follows the parent's pre-build staging; missing source/configuration is not relabelled as only a phone gate.

Accepted plan/addendum identities and requirement-level mapping remain in the worker's parent handoff. This document does not change Rev5/Library4 requirements or owner corrections. An online-confirmed historical-notice alternative for MESSAGE/SCHEDULE is only a separately proposed bounded-review contract, not a silent policy replacement.

# Returned-phone original-work preservation

This source implements Eric's selected local-preservation path. Ordinary phone assignment remains a named manager action. A small server preservation fact is distinct from confirmation or upload of the former employee's cleaning work. No server synchronization of every unsent work item is required before reassignment.

Use the existing protected native preparation activity to retain the original all-eight-namespace and complete browser inventory and obtain the original manager decision. The actual private native ACK owns one fixed ACTIVE-to-EMPTY enrollment transition. Its v3 encrypted durable command fixes the original employee, operation, source snapshots and one next storage partition before that transition. All original encrypted custody files, original browser profile, raw unknown values and required key aliases remain. The original browser data is retained in its existing private profile and encrypted custody archive; this change does not claim to newly encrypt the entire WebView profile.

A successful v2 successor observation now includes `restart_required: true` and the fixed next enrollment partition. Restart the app before the next enrollment. Only the eight fixed Custodial preference names, native private custody root and WebView data-directory suffix select the next partition. Other SDK preferences and Android's general no-backup directory keep their existing lifecycle. Canonical kiosk identity, package/UID and installation stay the same. The old WORK/browser writers remain HELD; its existing scheduled provider job and visible notifications are quiesced without deleting custody records or keys.

The DUMP-protected `RetainedEnrollmentMaintenanceReceiver` admits these exact explicit actions, with optional canonical `device_id` and only an existing `operation_id` as selection input:

- `org.memphiszoo.custodial.VERIFY_RETAINED_ENROLLMENT` reopens the authenticated native partition chain, compares retained private-file identities/hashes, decrypts the original credential and verifies its exact purpose HMAC. It reports original employee attribution and false work-acceptance/key-removal/assignment effects.
- `org.memphiszoo.custodial.REPORT_RETAINED_ENROLLMENT` sends that one fixed small preservation fact over the existing native authenticated transport. It sends no cleaning payload. The server joins the actual original manager decision and complete manifest; retries require exactly the original raw fact and return its immutable receipt.
- `org.memphiszoo.custodial.FINISH_RETAINED_ENROLLMENT` requires the original operation UUID. It can complete only that already encrypted v3 command against the same actual GCM/HELD/all8 predecessor or its exact successor. A same-process ambiguous SharedPreferences write remains blocked. It does not issue another manager decision, renew approval, create a different predecessor, replay work or clear an unknown snapshot. An already retained operation is verified rather than repeated. Older v2 DATA records cannot acquire this new authority.

The OS DUMP gate is mandatory. The broadcast must expose an identified external original sender on Android34 or later; missing sender identity, same-app sender, dirty intent/extras and an active maintenance flight are refused. Operator launch syntax and OS identity delivery have not been tested on a phone. The returned-phone/Wi-Fi-debugging workflow must verify these OS conditions during the separately authorized physical acceptance stage.

After the small preservation fact is recorded, the existing named manager assignment can move the physical phone to the next employee. The former credential receives a server-owned denial marker and can never authenticate ordinary work as the next employee, including observe-policy fallback. The enrollment consumer preserves that original credential instead of treating it as the next employee's predecessor. Current coverage and phone-admin displays exclude it from active enrollment. The next employee enrolls into empty partitioned storage; retained originals keep their former employee attribution and keys. Maintenance can select an older original operation through the authenticated native chain without caller-selected filesystem paths.

This file describes source behavior and the intended operator sequence. Actual AndroidKeyStore/WebView/notification/job behavior, private owning ACK/finalizer execution through reassignment, APK assembly and installation have not been performed or accepted. The legacy unbound removal API continues to refuse because it cannot prove all-eight/browser preservation. The earlier five failures that expected its direct erase remain preserved in historical evidence. Current tests exercise the owning preserving transition and still require the unbound erase to refuse; the current484-member compiled JVM suite passes. Those host tests do not establish real AndroidKeyStore or private finalizer execution. Do not interpret the host storage model or this document as release admission.

Eric deferred new retention, analytics, monthly/yearly rollups, inspection correlation and phase automation. None is introduced by this repair. No live data was purged or reassigned.
